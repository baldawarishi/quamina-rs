### PR 5: NFA Step Simplification Documentation & Test Rigor (Commit `e33139f` / PR #519)
**Focus:** Porting the smallTable `step` optimization.
**Tasks:**
- **Analysis Conclusion:** The upstream Go code removed a `stepOut` struct allocation that happened per-traverse during NFA stepping. Rust's value semantics and current `step()` / `dstep()` signatures already return primitive tuples and `StateId` directly, meaning this zero-allocation optimization is naturally achieved in our port.
- **Action:** I will add clarifying documentation to our `dstep` methods explaining the performance characteristics aligned with the upstream Go optimization.
- **Validation:** Ensure all NFA traversal tests accurately cover these edge cases.

### PR 6: Implement Get/Set Memory Budget APIs (Commit `5a50971` / PR #516)
**Focus:** The core functional API change that limits memory allocations for complex patterns.
**Tasks:**
- **Shared Budget State:** Modify the internal matchers to refer to a shared, mutable budget (e.g., an `Arc<AtomicUsize>`) rather than keeping independent static copies of `arena_byte_budget`.
- **Memory Estimation:** Implement a DAG traversal function on the matchers. Since matchers form a directed acyclic graph (via `Rc<MutableValueMatcher>`), the traversal will use a `HashSet` to ensure we don't double-count shared sub-graphs when summing up the `StateArena::estimated_byte_size()`.
- **Public API:** Expose `get_memory_budget` and `set_memory_budget` on the `Quamina` struct. `set_memory_budget` will return an error if you attempt to set the budget lower than the currently consumed memory.
- **Port Tests:** Port upstream's `TestStringFA` and `TestMemoryStress` (from `memory_cost_test.go`) to Rust to rigorously validate the memory budget behavior.
- **Final Sync:** Bump `.go-upstream-sync` to `53515a0`.
